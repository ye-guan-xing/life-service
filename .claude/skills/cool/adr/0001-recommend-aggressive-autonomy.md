# ADR 0001 — recommend 模式刻意激进自主

## 约束

- cool 的 `/cool --recommend` / `/cool-recommend` 设计目标是最大化 AI 在工作流中的自主决策。
- 方向性决策（intent / finishing-branch / scope-split-review）是可逆的；只有不可逆决策才需事前阻塞。
- 用户明确接受"静默改方向"的风险以换取流程流畅度。

## 选项

1. **激进自主 + 事后透明**（选定）—— 可逆 gate 自动推进；用审计记录 + 轻通知 + 可回退代替事前阻塞。
2. **保守自主 + 事前确认 gate** —— 为方向性决策加事前确认。
3. **纯自主，无透明** —— 一切自动推进，无审计。

## 拒绝理由

- 选项 2 拒绝：与既定设计意图相悖；事前确认 gate 正是用户拒绝的。
- 选项 3 拒绝：移除安全底线；"激进自主" ≠ "纯自主"——不可逆决策的 block 档是既有边界。

## 决策

recommend 模式自动推进可逆决策点。安全由事后透明（审计 + 轻通知 + 可回退）提供，非事前阻塞。真正不可逆决策的 block 档仍是边界。勿轻议在 recommend 模式加事前确认 gate——那与设计意图相悖。

## 不变量

- 可逆决策点在 recommend 下保持可自动推进。
- 不可逆决策的 block 档永不被绕过。
- 若某安全增强提议加事前确认 gate，应用前必须经用户确认——优先用事后透明。
